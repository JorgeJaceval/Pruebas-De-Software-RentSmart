# HU-10 — Casos de prueba y resultados (REN-10)

Historia: [REN-10](https://rentsmartpsf.atlassian.net/browse/REN-10). Alcance funcional: [HU-10](../HU-10.md). Registro de trazabilidad: 9 de octubre de 2026.

Los CA-01 a CA-06 conservan los criterios de la descripción de Jira. Se documentan **6 CP lógicos**, con los identificadores CP01 a CP06 ya utilizados en las pruebas de interfaz y backend. Cada caso reúne sus variantes válidas, negativas o de permiso; no equivale a un único test automatizado.

## CP

### Precondiciones y datos comunes

Existe una publicación «Sala de ideas»: descripción y condiciones completas, tipo sala de reuniones, comuna Providencia, ubicación referencial, capacidad 8, tarifa **12.000 CLP/h**, horario diario Santiago 09:00–18:00 y tres fotos. Se dispone de visitante, propietario, otra cuenta y administrador de prueba. Los estados inactivo/retirado se preparan en las fixtures; esto no implica que esté implementada la gestión administrativa de HU-18. Jest simula HTTP y Pytest utiliza PostgreSQL real con datos aislados.

### CP-01 — Detalle completo y acceso directo (CA-01)

- **Precondición/datos:** publicación activa con los datos comunes; respuesta pública que incluye únicamente el contrato permitido.
- **Pasos:** abrir desde «Ver espacio» del catálogo; comprobar cada dato y las tres fotos; recargar la URL directa `#detalle-espacio/{UUID}`; repetir como cuenta autenticada.
- **Esperado:** aparecen nombre, descripción, categoría, comuna/ubicación referencial, fotos, capacidad, condiciones, tarifa por hora y horario diario de Santiago. La URL directa conserva el detalle. No se muestran correo, identificador del propietario ni otros datos privados; la API conserva `Cache-Control: no-store`.
- **Resultado:** aprobado mediante automatización de interfaz y API.

### CP-02 — Visitante y retorno después del acceso (CA-02)

- **Precondición/datos:** sin sesión; publicación activa; credenciales válidas de otra cuenta.
- **Pasos:** consultar el detalle público y pulsar «Iniciar sesión para reservar»; recargar la ruta de acceso; iniciar sesión.
- **Esperado:** el visitante consulta sin autenticarse. El acceso conserva un destino UUID de espacio y vuelve al mismo detalle después del login, incluso tras recargar. La lectura autenticada usa Bearer y el botón de reserva sigue deshabilitado mientras la selección esté incompleta. Autenticarse no crea una reserva.
- **Resultado:** aprobado mediante automatización de interfaz; la API pública admite lectura sin sesión y la ruta privada requiere sesión válida.

### CP-03 — URL antigua, estados privados y fallos controlados (CA-03)

- **Precondición/datos:** publicación inexistente, inactiva o retirada; cuentas comunes; UUID mal formado; fallo SQL y respuesta inválida simulados.
- **Pasos:** consultar cada publicación como visitante y otra cuenta; consultar la inactiva/retirada como dueño y administrador; solicitar un UUID inválido; provocar error SQL o detalle inválido y reintentar tras corregirlo; provocar `401` en la lectura privada.
- **Esperado:** inexistente/no visible recibe `404` y no ofrece reservas; UUID inválido recibe `422`. Dueño/administrador ven detalle privado con aviso de estado y sin controles de nueva reserva. No adquieren permisos adicionales de edición por poder leer. Error SQL produce `503` sin secretos; la interfaz informa el fallo, permite reintentar y no lo confunde con un detalle válido. `401` elimina la sesión y los datos privados mostrados.
- **Resultado:** aprobado mediante automatización de interfaz y API.

### CP-04 — Imposibilidad de reservar el espacio propio (CA-04)

- **Precondición/datos:** sesión del propietario; publicación propia activa y variante inactiva; cuenta arrendataria distinta para comparar.
- **Pasos:** abrir el detalle con la sesión del dueño; comprobar sus controles; intentar creación directa de reserva por API; probar la guardia backend con dueño y arrendatario.
- **Esperado:** se informa «Este es tu espacio. No puedes reservarlo», no aparecen controles de selección ni solicitud. Backend obtiene la relación desde la sesión, devuelve `409` al dueño y no guarda reserva/pago. El arrendatario distinto supera la guardia para un espacio habilitado. Ocultar controles no es la única protección.
- **Resultado:** aprobado mediante automatización de interfaz, guardia y API de creación.

### CP-05 — Selección horaria y precio por hora (CA-05)

- **Precondición/datos:** publicación activa común; fecha futura `2026-11-01`; variantes 09:00–18:00 (9 horas) y 10:00–18:00 (8 horas).
- **Pasos:** comprobar controles y etiqueta CLP/h; completar fecha y el intervalo de nueve horas; cambiar inicio a las 10:00; comprobar las opciones disponibles de hora.
- **Esperado:** se entiende arriendo por hora en Santiago, sin precio diario supuesto. Las opciones respetan 09:00–18:00; nueve horas informa duración admitida de 1 a 8; ocho horas es válido. Seleccionar no ejecuta un POST ni anuncia reserva creada; HU-12 crea y revalida la reserva al solicitarla.
- **Resultado:** aprobado mediante automatización de interfaz; la creación y disponibilidad temporal se trazan a HU-12.

### CP-06 — Fotografía fallida (CA-06)

- **Precondición/datos:** tres fotos en la publicación común.
- **Pasos:** cargar el detalle y provocar error de carga en la primera imagen; consultar las otras imágenes, descripción y condiciones.
- **Esperado:** la primera imagen presenta «foto no disponible», conserva un texto accesible y no impide consultar las demás fotos ni los datos o condiciones. El resto del detalle sigue utilizable.
- **Resultado:** aprobado mediante automatización de interfaz.

### Evidencia y procedimiento reproducible

La ejecución ya registrada [Pruebas RentSmart #34](https://github.com/JorgeJaceval/Pruebas-De-Software-RentSmart/actions/runs/37877845587), revisión `2472f04bb1bb024de13c30afa667fc3c898c3d77`, aprobó **98 pruebas Jest en 11 suites y 114 Pytest**, compilación frontend, `alembic upgrade head` y `alembic check`. Esa revisión tiene el mismo árbol de código que `develop` en `8b7abf0f0f95a3336e7044ffe2b9715192fd7a4b`. Se usa como evidencia existente; esta actualización documental no ejecuta nuevamente las suites. Los 212 resultados son la regresión completa, no el número de CP de HU-10.

Para reproducir, instalar dependencias y preparar PostgreSQL como indica el [README](../../README.md). Desde `frontend`: `npm ci`, `npm run build` y `npm run test:ci`; focalizado: `npm run test:ci -- SpaceDetail.test.tsx Catalog.test.tsx`. Desde `backend`: `uv sync --frozen`, `uv run alembic upgrade head`, `uv run alembic check` y `uv run pytest -q`; focalizado: `uv run pytest -q tests/test_space_detail.py tests/test_public_catalog.py tests/test_reservations.py`.

Técnicas: particiones por rol y estado, pruebas negativas de permisos, valores límite de duración y errores de interfaz/contrato. Jest usa jsdom y HTTP simulado; Pytest usa FastAPI TestClient y PostgreSQL 17 con esquemas aislados. Se conserva una advertencia existente de deprecación de Starlette/TestClient, sin fallos. No se atribuyen pruebas manuales, E2E, rendimiento ni un porcentaje de cobertura no medido.

**Conclusión:** CA-01 a CA-06 cuentan con evidencia automatizada del alcance de consulta de detalle. **Done** es coherente para esta HU. El filtro temporal del catálogo y la ejecución de pago/cancelación pertenecen a otras historias; no se declaran implementados aquí.
