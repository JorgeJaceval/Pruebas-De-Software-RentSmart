# HU-01 — Registrarse (REN-1)

Como visitante, quiero crear una cuenta con mi nombre, correo y contraseña para poder publicar espacios y realizar reservas.

Fuente: `Historias de usuario.pdf`, página 7, y rangos comunes de las páginas 3 y 4. Tarea: [REN-1](https://rentsmartpsf.atlassian.net/browse/REN-1). Los requisitos y el flujo de uso están en [requerimientos.md](requerimientos.md).

## Comportamiento disponible

La sección **Crear cuenta** de la página inicial contiene los tres campos y sus mensajes de error. Al completar el registro se confirma la creación de la cuenta y se limpia el formulario. El registro no inicia una sesión automáticamente. La navegación al inicio de sesión de CA-01 depende de HU-02, todavía pendiente.

El nombre se recorta y debe tener entre 2 y 80 caracteres. El correo se recorta, se convierte a minúsculas y debe ser válido y único. La contraseña tiene entre 8 y 64 caracteres; conserva exactamente lo ingresado y se guarda como hash Argon2id.

El servidor genera el UUID y crea una cuenta con `is_admin=false`. El registro público acepta solo nombre, correo y contraseña. Las funciones de publicación y reserva corresponden a otras historias.

## Contrato de API

`POST /api/auth/register` recibe `name`, `email` y `password`.

| Código | Resultado |
| --- | --- |
| `201` | Cuenta creada; respuesta con `id`, `name` y `email` |
| `409` | Correo ya registrado; error asociado a `email` |
| `422` | Datos inválidos o campos adicionales; mensajes por campo |
| `503` | Persistencia no disponible; mensaje controlado |

Los errores contienen `detail` y `errors`. La API excluye los valores enviados, contraseñas, hashes y detalles internos de conexión de sus respuestas.

La migración `0001_create_users` crea la tabla y las restricciones de unicidad, correo normalizado y longitud de nombre. PostgreSQL resuelve los registros simultáneos mediante `uq_users_email`; la sesión que encuentra el conflicto revierte su transacción. La respuesta pública se prepara antes del commit y se devuelve después de guardar la cuenta.

Los textos deben poder codificarse como UTF-8. El nombre no acepta NUL y el correo se ingresa como dirección simple, sin nombre visible ni delimitadores `< >`.
